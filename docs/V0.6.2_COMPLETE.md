# v0.6.2 complete — migrate batch + download-root organization

**Package version:** 0.6.2

## Field abort (named)

Progress/`between_files` callbacks sat **outside** the per-file `try/except` in `run_library_move`. `LibraryMoveRunner` then **replaced** the in-progress report with `failed=1`. One file could already be on the library drive (field: 4.5 GB cross-volume copy to `K:`) while the rest stayed in `youtube\`. Evidence: [AUDIT_LIBRARY_MIGRATE_v0.6.2.md](AUDIT_LIBRARY_MIGRATE_v0.6.2.md).

## What shipped

- Callback errors no longer abort the batch; the runner keeps `moved`/`failed`/`errors`. Each file logs src/dst; failures use `log.exception`.
- Cross-drive: `copy2` → size verify → unlink source (`library/transfer.py`). Same-drive rename; `OSError` falls back to copy+verify.
- After migrate, auto **Scan library folder** for orphans under `library_root`.
- GUI attach starts a **background** site-folder repair: thumbs next to videos in `youtube/` and other media homes → `thumbnails/` (unique suffix on collision); leftover SQLite → `database/`; `.part`/junk **counted only**. Settings → **Repair folders**. Videos stay in per-site folders.
- `scripts/reset_library_state.ps1` (alias of `reset_library.ps1`) for a clean onboarding retest.
- Dedupe + junk triage remain as in v0.6.1 (Recycle Bin only).
